## When to use it

The options are algebraic expressions rather than numbers, and setting up the algebra
directly looks slow or error-prone.

Rather than manipulating symbols, pick a concrete value, compute the real answer, then
find which option produces it.

## The method

1. Pick a value for the variable — small, and easy to compute with.
2. Work the problem with that number to get an actual numeric answer.
3. Put the same value into every option.
4. Whichever option matches your number is the answer.

## Choosing the number well

- **Avoid 0 and 1.** They make genuinely different expressions collapse to the same value,
  so several options match and you learn nothing.
- **Avoid any number already in the problem**, for the same reason.
- **For percent problems, use 100.** Always. It makes every intermediate step readable.
- **For fraction problems, use a common denominator** — or a multiple of everything in
  sight, so nothing turns ugly.
- **If two options both match**, pick a second number and test only those two. This is
  normal, not a sign you did something wrong.

## The cost

You must test every option rather than stopping at the first match. That is the price of
the method, and it is why it earns its keep only when the algebra is genuinely awkward.
When a direct setup is two clean lines, do the algebra.

## The related method

If the options are *numbers* rather than expressions, use
[Backsolving From The Options](./Backsolving%20From%20The%20Options.md) instead. It is
usually faster, because you can start in the middle and eliminate half the list with a
single test.
